## What this is
An **Expense Tracker** MIS for a small organization — a university class project built in phases (Phase 0–6) per `docs/MASTER_PROMPT.md`, then Phase 7 (`docs/PHASE_7_PROMPT.md`, sub-phases 7A–7F approved) to close the original limitations. Staff record expenses, managers set budgets/approve/view reports+alerts, admin manages users/departments. All phases are now built: setup + health check (Phase 0), auth with roles (Phase 1), expense CRUD (Phase 2), budgets + approvals (Phase 3), MIS reports/alerts (Phase 4), admin pages + polish (Phase 5), seed/tests/docs (Phase 6), and 7A security/account management, 7B expense roles, 7C budgets/reports, 7D admin/data integrity, 7E notifications, 7F quality/CI/docs.

## Next.js 16 gotcha
`next.config.ts` enables `cacheComponents: true`, which **disables** the legacy `export const dynamic = 'force-dynamic'` route segment config. To force per-request rendering in a route handler, use `await connection()` from `next/server` instead (see `app/api/health/route.ts`). For pages/layouts that read `cookies()`/`headers()` (anything auth'd), prerender fails — mark them a blocking route with `export const instant = false` (see `app/(protected)/layout.tsx`).

## Security and account management (Phase 7A) — where things live
- **Deactivated / deleted users:** `lib/session.ts#refreshFromDb` re-reads the user on every page and API call. `getSession` (pages) `redirect('/api/auth/session-expired')`; `getApiSession` (API) clears the cookie and returns null → 401. `app/api/auth/session-expired/route.ts` clears the cookie and 303s to `/login?reason=deactivated`; `app/login/page.tsx` shows the message (client-side `useSearchParams` inside a Suspense boundary — `/login` is statically prerendered, so the message is not in the initial HTML). Deleted users get the same treatment (the pre-7A guard 401'd them too).
- **Change own password:** `ChangePasswordSchema` in `schemas/auth.ts` (mismatch + "different from current" refinements); `services/auth-service.ts#changeOwnPassword` requires the current password, re-hashes with bcrypt, clears `mustChangePassword` and audits `update` on `User`; route `POST /api/account/password` (rate-limited, and the only route allowed while a temporary password is pending); page `/account` (all roles, linked from the header) with `components/change-password-form.tsx`.
- **Temporary passwords:** `models/user.ts` gained `mustChangePassword` (default false). `services/admin-service.ts#resetUserPassword` generates (`lib/password.ts#generateTemporaryPassword`, `Temp-` + 12 crypto-random chars) or accepts a password, sets the flag and audits; route `POST /api/admin/users/:id/reset-password` takes `{}` or `{ password }`; "Reset password" in `components/admin/users-table.tsx` shows the password once in a row panel (never stored, never re-fetchable). Enforcement: `requireSession` answers 403 `{ error: 'Password change required' }` unless `allowPendingPasswordChange` is set, and `app/(protected)/layout.tsx` redirects every protected page to `/account/change-password`.
- **Forced change page:** `app/account/change-password/page.tsx` lives **outside** the `(protected)` group so the layout redirect cannot swallow it. `/account` (inside the group) redirects there while the flag is set; `app/login/page.tsx` sends the user straight there after login.
- **Rate limiter:** `models/rate-limit.ts` (`{ key, count, windowStart }`, unique `(key, windowStart)`, TTL index on `windowStart` of 60s) + `lib/rate-limit.ts` (`checkRateLimit`/`resetRateLimit`, now async; atomic `findOneAndUpdate` upsert with a retry on the duplicate-key race). Same 5-per-minute interface as Phase 1, keys `login:<ip>`, `register:<ip>`, `password-change:<ip>`. `clientIp(headers)` reads the first `x-forwarded-for` hop.
- **Sliding sessions:** `lib/auth.ts` — `SESSION_SECONDS` (8h), `ABSOLUTE_SESSION_MAX_SECONDS` (7d), `signSession(session, { issuedAt })`, `verifyToken` (session + `issuedAt`/`expiresAt`; falls back to `iat` for pre-7A tokens) and `shouldRenewToken` (renew under 2h left, only if `now + 8h <= issuedAt + 7d`). `getApiSession` rewrites the cookie on renewal. `mustChangePassword` is DB-fresh and never part of the JWT.
- **Verification:** `scripts/verify-phase7a.mts` — 59 checks: deactivation lockout + redirect chain, both password flows with role/tenant guards, HTTP + direct rate-limit tests, a second process (`scripts/rate-limit-probe.mts`) proving the shared counter, the three renewal cases, and the browser flows.

## Gotchas — gotchas while building
- `.env` must contain `JWT_SECRET` (and `MONGODB_URI`); missing `JWT_SECRET` makes every auth route 500. Added one.
- **Atlas IP allowlist (resolved 2026-10-24).** A non-allowlisted IP makes DNS/SRV and TCP to the shards succeed while the TLS handshake is refused with `tlsv1 alert internal error` (SSL alert 80) — so `/api/health` returns 503 and every DB-backed route fails. Fix is on the Atlas side: add the machine's public IP to the cluster's IP access list. Verified working after allowlisting: `/api/health` → `{"status":"ok","db":"connected"}`.
- Mongoose model files destructure from the **default** import (`const { Schema, model, models } = mongoose`) so they work under both Next.js and Node's native ESM loader (used by `scripts/`), which rejects named imports from CJS.
- `tsconfig.json` excludes `scripts/` — those files are run directly by Node (`.ts` extension imports) and are not part of the Next app type-check.
- Next 16 deprecated the `middleware` convention: the file is `proxy.ts` and the exported function is `proxy` (resolved in Phase 7A, warning gone). Proxy runs on the Node.js runtime and accepts `export async function proxy(req: NextRequest)` + the usual `config.matcher`.
- Scripts that import a model using a `@/` alias (e.g. `models/expense.ts` → `@/lib/constants`) **cannot** run under `node file.ts`: Node's native ESM loader can't resolve the alias. Run them with `npx tsx file.mts` instead (tsx resolves `tsconfig` paths; `.mts` is needed for top-level await because `package.json` has no `"type": "module"`). Models without aliases still run under plain Node.
- The expense form validates with the shared schema, so `parsed.data.date` is a `Date`; `JSON.stringify` would send an ISO datetime that the API's `YYYY-MM-DD` schema rejects. The form therefore sends the raw `date` string (`{ ...parsed.data, date }`). Caught by the Playwright form test.
- Playwright browsers are not installed by `npm install`; run `npx playwright install chromium` before browser checks.
- UI checks must wait for hydration before typing: a controlled input filled pre-hydration loses its value and a click falls through to a native form submit. The verify scripts wait for `__reactProps` on the target element first.
- Deleting `.next` while `next dev` is running — **or running `npm run build` between a dev-server stop and start** — leaves Turbopack in a reload storm (`✓ Compiled` before nearly every request, browser tabs refresh repeatedly). Stop all dev processes, `rm -rf .next`, start fresh; verified fixed by counting document requests (1 per load) and 0 spontaneous log lines over 30 s.
- Playwright's `framenavigated` also fires for **same-document** navigations (history updates): Next 16 dev fires one such navigation ~0.3 s after each load when Fast Refresh applies the first build (HMR `sync` hash `""` → `built` hash `"0"`). A reload detector must count `request` events with `resourceType() === 'document'`, not `framenavigated`, or it reports a false loop. This one is benign — no refetch, no reload.
- `pkill -f "next dev"` inside a shell command matches the *invoking shell's own* command line and kills it (silent, no output). Use `pkill -f "[n]ext dev"` (same trick for `[n]ext start`).
- Browsers log **every failed HTTP response** as a console error (`Failed to load resource: … 409/403`). A Playwright "no console errors" check must classify those separately from real JS/CSP errors, or deliberate failure tests (blocked delete, forbidden page) fail the run — `verify-phase5.mts` collects them in `failedRequests` and only unexpected statuses count.
- Mongoose casts ids for `.find()` but NOT inside `aggregate()` pipelines — `$match` needs `new mongoose.Types.ObjectId(...)` manually or nothing matches.
- The `Department` collection's own key is `_id`; a scope of `{ departmentId: ... }` must be mapped to `{ _id: ... }` before filtering `Department.find()` (otherwise the query matches nothing). Budget/Expense documents do have a `departmentId` field.
- Recharts 3: the line layer class is on the `<g>` (`svg path… .recharts-line-curve` matches either way, but `svg.recharts-line-curve` does NOT — the `<svg>` itself is `.recharts-surface`), and **zero-dimension bars are filtered out**, so a bar chart only renders rectangles for non-zero categories.
- With `cacheComponents` (Next 16), `export const dynamic = 'force-dynamic'` is a **build error** — the route must read the session/params and use `export const instant = false` instead, like the other protected pages.
- Notification dedupe relies on a **partial unique index** (`dedupeKey` is a string). Duplicate emissions are swallowed on error code 11000; without the index (e.g. `autoIndex: false` and no `syncIndexes()`) repeats would create duplicates rather than fail.
- `notifyBudgetCrossedAfterApproval` must exclude the just-approved expense from the “spent before” sum — the expense was pending, so a plain approved sum would already include it and the crossing would never be detected.
- Documents written before Phase 7D have no `isArchived`/`currency`. Read them with fallbacks (`doc.isArchived ?? false`, `currencyOf`), and never filter `{ isArchived: false }` in Mongo — old docs would disappear (same trap as `submitterRole`).
- `Intl` currency strings contain a non-breaking space between the code and the number (`KES\u00a0100.00`) and prefix the minus sign (`-KES\u00a050.00`). Assert against `formatAmount(...)` output rather than hand-written strings, or comparisons fail on invisible characters.
- Archived departments block *new* assignments only. Existing members keep their department, can still be edited, and their budgets/expenses keep counting; re-enable writes with unarchive rather than deleting history.
- Audit rows can share the same millisecond, so the viewer sorts by `createdAt` **and** `_id`; without the tie-breaker pages can repeat or skip entries.
- Prettier is clean repo-wide since Phase 7F, but `format:check` succeeds partly because `.prettierignore` excludes build output, `package-lock.json`, `public/`, `*.md`, `.env*` and the agent scaffolding (`.agents`, `.claude`, `agent`). If a directory of generated/vendored files is added, ignore it rather than formatting it.
- `lib/db.ts` throws at **import time** when `MONGODB_URI` is unset. Integration tests therefore start `mongodb-memory-server` in `beforeAll`, set `process.env.MONGODB_URI`, and only then `await import()` the services (all service imports in that file are dynamic on purpose). Static imports would fail before the server exists.
- `mongodb-memory-server@11` requires Node **>=20.19.0**, which is why the CI workflow pins `node-version: 20.19` rather than `20`. Its postinstall downloads the mongod binary; if npm script execution is blocked (as in this sandbox), the binary is fetched lazily on the first `MongoMemoryServer.create()` instead — the tests still work, just later.
- With `cacheComponents`, a `redirect()` raised inside a server component is served as a **200 document** whose RSC payload makes the browser navigate — there is no 3xx and no `Location` header, so HTTP checks must accept either form (the Playwright checks are the authoritative proof of where the user lands).
- Never redirect a deactivated user straight to `/login`: the proxy only verifies the JWT, so the still-valid cookie bounces between `/login` and the protected page forever. Route it through `/api/auth/session-expired`, which can clear the cookie during a request.
- The forced change page must stay outside `app/(protected)/`: the layout redirects every protected page to it and would redirect it to itself.
- The per-IP rate limits key off the first `x-forwarded-for` hop, which a client can spoof when no trusted proxy sets it. Acceptable for this project; a deployment behind a proxy should read a trusted header (or key login on the email too).
- The `RateLimit` TTL index only exists once Mongoose creates it (`autoIndex`, on by default). A production deployment with `autoIndex: false` needs `RateLimit.syncIndexes()` once; the window query is still correct without it, stale docs just linger.

## Conventions

- Agent `id` values: lowercase letters, numbers, hyphens only (e.g. `code-reviewer`).

## Gotchas
- `reasoningOptions` requires exactly one of `max_tokens` or `effort`.
- `inheritParentSystemPrompt` cannot be combined with `systemPrompt`.
- Referencing store agents from `spawnableAgents` requires the fully qualified id including publisher and version (e.g. `codebuff/file-picker@0.0.1`); local agents in `.agents/` use the bare id.
